# Independent receipt-protocol review

Scope: committed `0609bf2` compared with `a21300c`, read through `git show`/`git diff` on October 19. New uncommitted integration work was excluded. Requested reviewer model: gpt-6-sol.

**Verdict: no concrete blocking defect found in the committed receipt lifecycle.** The prior lifetime ceiling is removed without permitting an acknowledged old batch to run again. `applyBatch` accepts effects only at `closedThrough + 1`, stores one active digest and exact receipts in the same mutation, returns those receipts for an identical retry, and returns a no-write cursor for closed, occupied or gap sequences (`backend/convex/librarySync.ts:236-265`). `acknowledge` closes only a matching active sequence/batch/digest and retains the content-free cursor (`:267-281`). The owner is derived from the verified JWT and checked against the short-lived binding for both mutations (`:17-39,227-233`).

Native settlement is coherent with that server state. Both platforms freeze a bounded frame and persist it before send; an accepted reply settles exact operation IDs/revisions and persists an acknowledgement before the next frame can freeze (`ios/Hadithly/Core/GuestData/GuestMergePlanner.swift:296-342,363-380`; `android/app/src/main/kotlin/com/hadithly/app/core/data/LibrarySync.kt:71-151`). If a restored backup presents a closed or occupied sequence, `adopt` archives the available frozen original as historical recovery, leaves never-frozen pending work intact, and takes the actual cursor; a different active server batch is acknowledged only after its proof is persisted (`GuestMergePlanner.swift:345-380`; `LibrarySync.kt:120-151`). The store wrappers reject a different owner, including the nested active receipt owner, and do not recreate erased partitions (`ios/Hadithly/Core/GuestData/GuestDataStore.swift:380-405`; `android/app/src/main/kotlin/com/hadithly/app/core/data/GuestStore.kt:347-380`).

Conditional undo no longer depends on compacted operation rows. Facet restore checks the current domain mark's deletion ID and remove kind before changing an absent facet; folder restore checks the matching delete mark and reports each member restored, superseded or missing (`backend/convex/librarySync.ts:97-119,165-179`; `backend/convex/lib/librarySyncMarks.ts:5-16`). Account deletion removes bindings, streams, marks and folder aliases; a later apply cannot recreate a deleted account (`backend/convex/users.ts:359-367`; `backend/convex/librarySync.test.ts:75-91`).

The committed tests exercise lost response before ACK, repeated ACK, replay after compaction and later removal, occupied fork, sequence gap, compacted undo, owner rejection and 100 actual apply/ACK cycles after a seeded 10,000 cursor (`backend/convex/librarySync.test.ts:32-55,185-247`). Native store tests cover durable ACK reopening, historical recovery, active proof and wrong nested owner (`ios/HadithlyTests/GuestMergePlannerTests.swift:150-226`; `android/app/src/androidTest/kotlin/com/hadithly/app/GuestMergeRaceTest.kt:184-254`). The 100 cycles do not prove 10,100 actual cycles, as `docs/LIBRARY_SYNC_PROTOCOL_VERIFICATION.md` correctly states.

**Remaining gates, not findings on this commit:** restored backups cannot recover private edits newer than the backup; server-behind gaps preserve available frozen intent for reconciliation rather than silently replaying it. Installed-schema migration, large-folder continuation, vanished-anchor handling, Android suspended storage-commit cancellation, account-scale export/erasure, actual auth/device delivery and the old sign-in `clearAll` path remain open in `docs/LIBRARY_SYNC_PROTOCOL_VERIFICATION.md`.
