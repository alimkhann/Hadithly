# Coordinator collection integration review

Read-only source review, October 20. Scope is the new `collectingOutcome` transition and real coordinator/page transport wiring. I found **no concrete proof, owner, cursor or data-loss blocker in this bounded collection phase**. I did not run native suites. This is not settlement, export, pruning or public-producer approval.

A direct accepted manifest receipt is checked against the still-frozen single operation, its ID/revision, batch ID and command kind before `collectingOutcome` is saved (`ios/Hadithly/Core/GuestData/GuestMergePlanner.swift:696-720`; `android/.../core/data/LibrarySync.kt:245-269`). The committed proof parser requires exactly one manifest receipt, valid identity/count fields and a bounded generation (`GuestMergePlanner.swift:427-461`; `LibraryOutcomeJournal.kt:76-100`). The store separately checks the response owner against its captured owner (`GuestDataStore.swift:389-428`; `GuestStore.kt:365-404`). This rejects malformed mixed/negative manifest receipts before a journal page or ACK.

For a committed cursor reached through reconcile, retirement or ACK, `adopt` validates the cursor, accepts a matched origin only when the observed pending proof and frozen `intentDigest` agree, and otherwise moves the frozen changes to historical recovery before entering collection (`GuestMergePlanner.swift:649-694`; `LibrarySync.kt:207-249`). A polled accepted response uses the same matched-or-historical split (`GuestMergePlanner.swift:747-763`; `LibrarySync.kt:300-322`). Once collecting, freeze and further adoption reject; `nextSequence` stays at the outstanding slot and `acknowledgement` is nil. The state-roundtrip and fork tests cover these routes (`GuestMergePlannerTests.swift:215-275`; `GuestMergeRaceTest.kt:218-263`).

The coordinators look for collection before poll/ACK/freeze/send, pass the active binding to `outcomePage`, and check session generation across the network await. They continue only through collecting/verifying steps and stop at a complete or unavailable journal without ACK or sending queued changes (`GuestMergePlanner.swift:923-984`; `LibrarySync.kt:482-553`). The store rechecks owner/deletion/partition before persistence (`GuestDataStore.swift:548-612`; `GuestStore.kt:458-491`). Both projections suppress an unconfirmed bounded restore and keep a matched delete overlay only below the authoritative Saved revision (`UserLibraryModel.swift:646-650`; `LibraryProjection.kt:26-30`; partition `projectedFrozenChanges`). This avoids presenting a guessed partial Undo as complete.

Open by design: final journal settlement must recheck the persisted matched intent before releasing the frozen source, preserve historical/unavailable evidence in export, and ACK only after a durable terminal checkpoint. The new code explicitly stops before those steps. Existing whole-file partition scale and public producer remain gated.
