# Final held-frame fingerprint review

Read-only recheck of the intent-digest fix, October 19. The earlier clone cases were red before this change in `/tmp/hadithly-held-frame-clone-red-ios.log` and `-android.log`. Full backend/native final runs were still in progress; no pass is inferred here. Public async folder production and >500 support remain disabled.

**Verdict: the prior P1 false-confirmation path is fixed in current source; no new blocker found in this bounded delta.** The pending server proof now carries `intentDigest` computed from the immutable batch at hold time while retaining the existing `syncBatchDigest` for receipt identity (`backend/convex/lib/librarySyncFrames.ts:24-49`; `lib/librarySyncPolicy.ts:58-75,141-165`). Both native `adopt` paths keep a local frozen original only when sequence, batch ID **and** computed intent digest match the pending proof. Otherwise they archive the original as historical recovery (`ios/Hadithly/Core/GuestData/GuestMergePlanner.swift:500-519`; `android/app/src/main/kotlin/com/hadithly/app/core/data/LibrarySync.kt:199-219`). On terminal poll, both recheck the local fingerprint before using that frozen batch for exact receipt settlement; a different clone instead adopts only the server committed proof for ACK (`GuestMergePlanner.swift:555-570`; Android `LibrarySync.kt:257-275`). The server's owner-checked poll matches the request's pending intent digest while the slot is pending (`backend/convex/librarySync.ts:264-276`).

The fingerprint encoding is explicitly typed: UTF-8 byte lengths for strings, tagged array/object lengths, sorted object keys and IEEE-754 bits for finite numbers (normalizing signed zero) (`backend/convex/lib/librarySyncPolicy.ts:146-165`; `ios/.../GuestMergePlanner.swift:369-388`; `android/.../LibrarySyncCodec.kt:14-30`). Backend-generated vectors include Unicode, fractional/exponent numbers and folder commands; iOS and Android tests decode those vectors and compare their native digest (`backend/convex/lib/librarySyncPolicy.test.ts:74-88`; `ios/HadithlyTests/GuestMergePlannerTests.swift:63-83`; `android/app/src/androidTest/kotlin/com/hadithly/app/GuestMergeRaceTest.kt:75-92`). This directly covers the representation drift that would make a fingerprint unsafe.

**Limits:** a malformed local frozen source/operation mismatch is still treated as recoverable invalid data, not proof of server acceptance. Held-frame expiry, account and installed-schema gates, and the future terminal success publisher require their own end-to-end verification. This review closes only the same-ID/different-intent clone risk.
