# Logical folder effects implementation review

Read-only source review, October 20. Tests were running. The public async-folder producer and native outcome collector remain disabled; this is an internal transition review, not a >500 or A2 completion claim.

**Verdict: no concrete blocker found in the reviewed internal state transitions.** The earlier contract P1s are addressed: `beginFolderRestoration` changes one deletion handle to `restoring` with a single `operationId` and rejects a competing ID; each page renews an inactivity lease, and final visibility flip gives the restored handle a fresh result-retention window (`backend/convex/lib/savedFolderTransitions.ts:55-118`). The test cases stage near expiry and exercise competing Undo IDs (`backend/convex/savedFolderTransitions.test.ts:112-152`).

The delete effect rechecks exact owner, folder identity, captured membership epoch/metadata time and folder mark before one transaction deletes the folder row, stamps a tombstone, advances Saved version and publishes a bounded terminal receipt (`savedFolderTransitions.ts:27-53`). Raw member pointers remain but `effectiveSavedMembership` projects them as no folder with a clock floor at deletion time (`backend/convex/lib/savedMembership.ts:14-28`). Thus an old 75,000 no-folder observation after a 100,000 delete cannot destroy Undo eligibility even when raw pointer time is 50,000. Staging records per-member dispositions without making any folder visible, and an accepted concurrent move/removal clears its stage and adjusts `restoring` counters in the same transaction (`savedFolderTransitions.ts:80-118`; `savedMembership.ts:30-40,76-102`). Final totals are frozen in `restored`; later edits clear a stage without rewriting historical counts. The interleaving test covers pre/post-flip clocks and missing/superseded members (`savedFolderTransitions.test.ts:89-110`).

An existing same-name destination is locked through `savedFolders.transition`; a new destination is created or reused only in the final flip (`savedFolderTransitions.ts:69-75,106-118`; `savedMembership.ts:8-12`). Both legacy and sync physical structural deletes/restores call the stability guard (`backend/convex/library.ts:783-830`; `backend/convex/librarySync.ts:74-125`). Materialization rewrites at most four manifest facts per step and releases the destination lock only at completion; effective reads and owner export use the phase-aware membership resolver (`savedFolderTransitions.ts:151-187`; `library.ts:849-886`; `users.ts:275-287`). Unconsumed expiry materializes old orphan pointers to a deletion clock before purging facts/mark, while restored expiry waits for visible materialization; owner erasure fences late workers (`savedFolderTransitions.ts:127-187`; `backend/convex/lib/savedFolderManifests.ts:103-127`).

**Cutover limits:** the current native settlement types still reject new bounded manifest outcomes until the outcome-page collector exists. Public producer, owned read/export pagination, installed-schema migration, hosted byte/transaction evidence and real native/device journeys remain open. The 501/2,001-member fixtures are local Convex tests, and their pending run cannot be called green in this review. No implementation or cloud change was made here.
