# Refinement C falsification — October 19

**Verdict: keep C as a smaller design candidate, but reject it as a complete contract as written.** Its O(1) logical delete plus one current per-item restore slot avoids A's member-fact copy per deletion and B's new authoritative membership table. The core can be sound if every writer and reader uses one effective-membership rule. That rule, the receipt outcome, and the one-time deletion handle are presently unspecified; implementing only the proposed fields would lose Undo intent.

## Concrete counterexample in the current code

An item points to folder F with `folderUpdatedAt=50`. C deletes F at operation time 100, leaving that pointer as an orphan. A delayed `membership_put none` at 75 then reaches current `librarySync.ts:149-164`: it compares 75 with the raw 50 and raw `folderId=F`, accepts the removal, and erases the pointer. Undo of the deletion now cannot restore the item even though that command predates the delete. Current physical deletion stamps a per-member mark at 100, which prevents this. An orphan must therefore have effective membership state `none` and effective clock at least the deletion time, obtained through an owner-scoped deletion handle keyed by the old folder ID. All account, legacy and guest-merge writers must use that rule; `guestMerge.ts:228-248` currently can retain or write a raw folder pointer with an older timestamp. During a restore job, an accepted move after deletion but before the final flip must clear the stage and decrement its count; a delayed older command must not. After the flip, the visible staged destination and `restoreAt` become the effective value/clock until materialization. Every write, `same` comparison, conditional undo, projection and export must use this phase-aware rule.

## What C can and cannot prove

- A `[userId, folderId, folderUpdatedAt]` index, queried by owner/folder with `.order("desc").first()`, gives a bounded maximum read. Convex documents indexed descending queries and serializable, atomic mutations; this supports the intended one-transaction delete if all insert/move-to-folder paths validate the live folder row and all move-away paths use effective clocks. A focused concurrent-insert/move test is still needed; an index read is not a substitute for migrating the writers. [Indexes](https://docs.convex.dev/database/reading-data/indexes/), [OCC and Atomicity](https://docs.convex.dev/database/advanced/occ).
- Raw orphan pointers identify the **remaining eligible** set. They do not retain the original set once an item moves, loses its last Saved facet, or is erased. C can truthfully return a bounded terminal outcome such as destination plus the exact count staged at the flip. It cannot reconstruct current `folder_restored` per-member `restored/superseded/missing` arrays—or even those category totals—without a deletion-time manifest or maintained aggregate counters. Drop the detailed claim from the wire/native UI; never label the scanned subset as the complete original set. The original content available only on the client stays in account-scoped recovery/export.
- `stagedCount` can be exact at the flip only if stage insertion, accepted move/removal, item deletion, and count update share transactions; after the flip, freeze the terminal count and track materialization separately. A worker patch must recheck raw pointer, stage job ID and effective clock so it cannot overwrite a later move. Destination/source structural operations, including legacy calls, must wait or resolve against the job; otherwise a same-name destination can disappear while staging.
- A deletion handle needs explicit states `deleted → restoring(job) → consumed(destination)` or `superseded`, keyed by owner and deletion operation. A duplicate restore returns the same job/result; a new old-handle command after a later destination delete cannot reactivate old orphans or recreate a same-name folder. Lock one active structural transition on source and destination; queued operations must re-evaluate current clocks when they run. Handles and job slots need an indexed bounded cleanup rule that does not invalidate an already frozen offline Undo; indefinite small handles are still unbounded history, so state the retention/expiry contract honestly.
- The existing stream has only `accepted` with a committed final receipt or `reconcile` (`librarySyncPolicy.ts`); `applyBatch` stores that receipt atomically and `acknowledge` can close it (`librarySync.ts:236-329`). A staged restore needs a distinct server-held pending frame keyed by owner/client/sequence/digest. Retries return pending; the worker converts it to **one terminal exact receipt**; only that receipt can be locally settled and ACKed. `retireInvalidFrame` must not advance past a pending job or call it no-effect. A cancellation path would need separate proof that no visible effect occurred. A folder-only frozen frame is sensible, but old mixed frozen frames require a truthful migration result, not blind replay or silent retirement.

## Comparison and next proof

C is materially smaller than B if the current Saved item remains the single membership record, and uses less per-deletion storage than A. It inherits A's necessary paginated Saved/export read migration and all-writer audit. Its gap is semantic rather than a Convex index limitation. Prototype the effective-membership helper and state machine before selecting it: reproduce the `50/100/75` stale-removal case; interleave a valid post-delete move before and after the restore flip; delete/recreate/restore/delete the same normalized name; kill the worker after stage, after flip and during materialization; replay and retire a pending frame; verify per-call row/byte limits at 501 and a much larger member count. If those tests require copied original member identities to satisfy the desired receipt, choose A instead. Local tests do not establish authenticated two-device delivery.
