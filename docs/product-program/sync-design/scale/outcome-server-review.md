# Outcome-page server boundary review

Read-only review, October 20. I found **no concrete blocking defect** in the new server page boundary. The parent was running tests; I did not run them or infer native/public readiness.

`outcomePage` derives the owner from verified identity and a live owner-bound capability (`backend/convex/librarySync.ts:283-290`; `lib/librarySyncIdentity.ts:7-20`). The helper requires the currently outstanding committed stream slot to match client key, sequence, batch ID and digest, then matches receipt ID, phase, manifest ID and generation (`lib/libraryOutcomePages.ts:6-17`). Batch operation IDs are unique under `validateSyncBatch`, so receipt ID is unambiguous within that committed proof (`lib/librarySyncPolicy.ts:115-126`). Pending and acknowledged slots have no page authority; the tests exercise both (`savedFolderTransitions.test.ts:343-354`).

Deletion pages deliberately read the original manifest identity rows even while Undo changes their dispositions, and label them `deleted` rather than reading mutable disposition (`lib/libraryOutcomePages.ts:27-39`). Restore pages require the final `restored` state and check receipt destination and frozen category counts against it (`:29-31`). The transition flips visibility and publishes that receipt in one transaction (`lib/savedFolderTransitions.ts:105-118`). Manifest expiry or purging returns explicit `detail_unavailable`, not an empty completed page (`lib/libraryOutcomePages.ts:23-26`); the expiry test covers it (`savedFolderTransitions.test.ts:356-364`). A zero-member manifest returns an explicit terminal page (`:391-396`).

The query reads at most 50 indexed member facts, checks contiguous ordinals and exact expected page length, and caps serialized response at 64 KiB (`lib/libraryOutcomePages.ts:33-43`; `lib/librarySyncPolicy.ts:13-14`). The member schema contains only IDs, ordinal, one clock and disposition (`schema.ts:574-579`), so this fixed row bound also bounds the read volume; there is no full-member collection in the page query. The tests cover 501 rows, repeatability, cross-owner/proof mismatch, missing ordinals, bad counts and expiry (`savedFolderTransitions.test.ts:274-396`).

Remaining integration requirement: the native collector must verify category totals over *all* persisted restore pages and retain local originals when detail is unavailable. The server cannot establish a full-page aggregate inside one bounded query. Current native settlement still rejects manifest outcomes, and the public producer is not enabled; this review certifies neither.
