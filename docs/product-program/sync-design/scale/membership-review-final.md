# Final membership-boundary review

Read-only review of the current correction to the `b198c18` membership diff, October 19. Tests were still running; folder jobs and full A2 are outside scope.

**Verdict: the aggregate-clock P1 is fixed in source; no remaining blocker found in this bounded change.** The V2 payload now carries optional `folderUpdatedAt` independently of Saved-item `updatedAt` (`backend/convex/guestMerge.ts:72-82`). iOS and Android planners copy the guest membership's own timestamp into that field, while later note edits change only the aggregate item time (`ios/Hadithly/Core/GuestData/GuestMergePlanner.swift:129-145,178-181`; `android/app/src/main/kotlin/com/hadithly/app/core/data/GuestStore.kt:464-479`). `guestMerge` passes the explicit membership clock to `writeSavedMembership` and never uses the aggregate clock for placement (`guestMerge.ts:229-244`). The focused test covers note 5,000, old folder intent 1,500 or unknown, and cloud placement 3,000 (`backend/convex/librarySync.test.ts:511-526`).

For an older payload without a membership timestamp, the helper's `claim_if_unset` branch writes only when the current item has no folder **and** no finite placement/deletion mark. It does not stamp a fabricated clock or operation mark; an existing cloud placement or prior explicit removal yields `unversioned_cloud` (`backend/convex/lib/savedMembership.ts:18-40`). The same rule is available to persisted native `membership_put` with unknown draft time; it cannot target `none` (`backend/convex/librarySync.ts:150-162`; `lib/librarySyncPolicy.ts:29,52,114-117`; `android/.../core/data/GuestStore.kt:326-334`). The test seeds an unknown claim with a deliberately large placeholder operation time, then proves a later explicit remove at 2,000 succeeds and a repeated unknown claim cannot replace it (`librarySync.test.ts:528-546`). This preserves old-client compatibility without granting false recency.

The ordinary dated path still rejects foreign folders, keeps overall `updatedAt` monotonic, and stamps the membership mark only for a real accepted write (`savedMembership.ts:23-40`). Same-value older/equal observations leave the causal deletion mark intact, while a different equal-time placement ties in favor of cloud. Native projections intentionally hide an unknown-time claim while it is still pending/frozen; they display it only after a confirmed result or subscribed snapshot (`ios/Hadithly/Core/GuestData/GuestMergePlanner.swift:418-432`; `android/app/src/main/kotlin/com/hadithly/app/core/data/LibraryProjection.kt:29-40`).

Limits: old timestamp-less drafts cannot override an existing cloud placement, even if the user actually moved later; that intent remains a recoverable conflict rather than a guessed ordering. Tests and generated-wire checks must pass before marking this repair verified. Large-folder continuation, real account/device proof and all wider A2 gates remain open.

## Frozen-frame and metadata addendum — October 19

**Scoped confirmation; no new blocker found.** Both native admission functions now validate the full frozen batch and require an unknown-time membership draft to carry `claim_if_unset`, so an older persisted guessed-time command follows the fenced historical-recovery path instead of being sent (`ios/Hadithly/Core/GuestData/GuestMergePlanner.swift:285-307`; `android/app/src/main/kotlin/com/hadithly/app/core/data/LibrarySync.kt:58-74`). `freeze` rejects a frozen batch whose wire operations differ from its stored source changes without removing either representation (`GuestMergePlanner.swift:397-401`; Android `LibrarySync.kt:129-134`). This is the right failure boundary: retirement of a mismatched representation could discard the only original value. Android now rechecks session after the suspending claim, ACK read, and frozen-state read before dispatch (`LibrarySync.kt:398-431`). The added native cases cover guessed clocks, malformed frozen retention, projection, recovery and serialization; final results were still running.

`guestMerge` checks note/item metadata clocks before any merge effects (`backend/convex/guestMerge.ts:97-107`), so unknown membership mode cannot make a future or nonfinite note/item timestamp valid. One limited validation inconsistency remains: the optional `folderUpdatedAt` is omitted from that upfront check and is validated by `writeSavedMembership` only when a referenced folder resolves (`guestMerge.ts:230-244`; `lib/savedMembership.ts:23-24`). A malformed folder clock with an absent folder reference is ignored rather than rejected, with no placement write; it does not reopen the aggregate-clock overwrite. Keep this in boundary tests if strict malformed-payload rejection is required. The old unresolved-folder behavior and full A2 gates remain separate.
