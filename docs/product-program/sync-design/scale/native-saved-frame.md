## Grounded requirement

The verified backend serves owner/version/root/input/start and one private fact per
page, followed by an opaque next or terminal completion token/total. Five sources
are folders, canonical items, legacy bookmarks, favorites and notes. Missing public
targets remain private facts; public summary hydration is separately eventual.
Native wire must derive actual validators, rather than mirror them manually.

Both native apps currently cache a complete joined snapshot in partition JSON.
Confirmed pruning, projected folder deletion, manifest settlement and retention all
read that snapshot's version. Partial private pages must not cross those barriers.
The eventual active pointer and complete private revision belong in the same row
database as the private rows, with no Android AtomicFile atomicity claim.

incremental projection plus compact replay ledgers. Preserve canonical-last values,
first encounter order, earliest facets, existing aggregate updatedAt rules and
strict note timestamp ties. Empty folders and private missing-target references
survive. Neither whole-library arrays nor repeated partition JSON writes are viable.

and at commit. Exact replay, source identity, phase order, ordinal continuity and

responses must fail without recreating state. Restart/unavailable preserves the
previous active base. Bound every read, write, verification, cleanup and export step.
