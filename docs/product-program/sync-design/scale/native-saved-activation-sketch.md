# Selected A design: activation/lifecycle implementation sketch

Continue selected candidate A, not a redesign. Parent sole implementation owner.

Usage: beginSavedAssembly(owner) returns current candidate or starts a new one after its predecessor was activated. collectSavedStep remains unchanged. activateSavedGeneration(lease,isCurrent,fetchTerminal) performs final exact server completion recheck and returns active(handle)/restart/unavailable. activeSavedGeneration(owner) and activeSavedPage(handle,after) inspect bounded verified private rows. No production subscription or barrier consumer switches in this component.

Add optional activeData and retiringData to existing owner header, storing a bounded typed generation record {lease,checkpoint}; require exact owner/scope/epoch, checkpoint validation and Prepared for active. Pointer + candidate checkpoint + old active retirement + export clock mutate in the SAME row DB transaction. SwiftData optional additive fields; SQLite v4 adds two nullable columns to v3, retains v1/v2->v4 via existing schema creation. No AtomicFile activation authority.

Current candidate's lease/checkpoint remain the header fields. First activation records current prepared candidate as active. Calling begin afterward preserves active and replaces candidate with same epoch/new random generation/empty checkpoint. Second activation moves prior active to retiring and flips active, only if no retiring record exists. At most active+candidate+retiring. Lost activation return is idempotent for exact already-active prepared lease, no extra export-clock change. Active handles have store-created immutable identity/version and every read revalidates current active equality; a stale handle cannot continue reading retired rows.

Capture exact prepared checkpoint before await. Single-flight shares collector guard. Recheck session after await and inside IO on Android; then transaction rereads exact lease/checkpoint/incarnation/erase fences. Confirm requires same owner/root/version/completion/start/total and empty facts. Strict saved_changed reply marks candidate Restart; Unavailable marks stopped, preserving prior active. Invalid reply, network failure or save failure preserves prepared state and old pointer. Reject candidate version older than active. A cloned collector that advances/replaces/erases during await fails CAS; first successful identical activation can return same handle.

Explicit replaceSavedCandidate(lease) requires lease not active and no retiring row; moves abandoned candidate to retiring and sets fresh candidate in same transaction. This handles binding restart/unavailable and explicit abandonment. cleanupSavedGenerationStep(owner) validates retiring differs from active/current and removes <=8 rows from the first nonempty raw/page/projection table using scoped indexed key ranges. Only after all three are empty clear retiringData. Each step bumps clock atomically. No unbounded per-call loop. New begin and further replace/activation block while a retiring record would be overwritten, so failures cannot accumulate generations. Old active stays readable during collection/cleanup.

Export header emits current candidate metadata plus bounded active/retiring metadata without opaque tokens; raw/page/projection sections already cover all retained collections. Export active booleans become truthful. Erasure existing owner scope marker hides all generations immediately and existing scope-key cleanup includes all children and optional metadata. Missing parent + retained children still refuses admission.

Prove on real disk both platforms: no active before final check; mismatch/restart/unavailable/network failure preserve old active; final check CAS and stale session/erase race; exact activation replay no clock bump; old active read during new collection; second activation invalidates old handle and retains prior rows; bounded cleanup reopen then third refresh; failed candidate replacement without overwriting retiring; v3->v4 and old iOS model additive data; export active/retiring with redacted proofs and mutation fence. Android SQLite abort tests actual pointer atomic rollback; iOS recoverable save failure remains gate, logical rollback tested only.

All four production observation consumers, bounded UI/public hydration, joined cache retirement, throughput, full partition/export, actual SDK/device/deployment gates remain OPEN. Internal active inspection here has no effect on current production ACK authority.
