# Original-source placement for terminal settlement

**No correctness requirement mandates attaching the local original to the journal before ACK.** A `LibraryRecovery.outcome(binding/status, original: LibraryLocalChange?)` in the existing owner partition is sufficient if the store commits that recovery entry, removal of `frozen`, sequence advance and exact ACK intent in **one** SwiftData/AtomicFile partition write, after verifying the already-durable matching terminal journal. The network ACK must follow that write. On a failed write, frozen original and no ACK remain; on reopen after a successful write or lost ACK reply, the recovery original and ACK intent remain together. The existing frozen restore payload is capped at 500 IDs by admission (`GuestMergePlanner.swift:286-303`; Kotlin `LibrarySync.kt:100-110`), and no collected member array enters the partition.

The settlement must still recheck `matched.intentDigest`, batch operations, receipt ID/revision/phase, owner and journal binding. Store `original` only for a matched frozen command; a historical receipt gets `original=nil` and retains any separately archived historical change. A partial restore or `detail_unavailable` must keep the compact recovery entry and all journal rows; `proof_unavailable` cannot settle. A fully successful matched delete still needs its short Undo receipt and exact journal identity set. The Saved-revision barrier and restore alias mapping happen in the same partition transition. Recovery/export must combine partition entries with subject+namespace journal discovery, including journal orphans, without claiming a partitionless orphan has local source.

The tradeoff is explicit: local original recovery depends on the partition's continued durability. Current production partition removal is tied to account deletion and journal erasure; the separate partition reset is test-only (`GuestDataStore.swift:476-495`; `GuestStore.kt:437-464`). If a future cleanup can discard the partition while retaining recoverable journal evidence, it must migrate those originals first or forbid that cleanup. The existing whole-partition size gate also remains open. Attaching source to the journal now adds a mutable journal field, export-clock bump and cross-store ordering without strengthening the present ACK atomicity guarantee.
