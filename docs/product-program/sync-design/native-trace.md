# A2 native sync trace (read-only, October 18)

This traces source behavior and the local red diagnostic. It does not establish a real Clerk/Convex account transition or cross-device delivery. Domain terms follow `CONTEXT.md`: a Saved item combines independent facets, and a reading position has a semantic anchor plus disposable page hint. `docs/product-program/sync-design/current-trace.md` records the red note/position deletion using each real persistence store.

## iOS

1. `UserLibraryModel` branches on `Clerk.shared.session != nil` supplied by `AppEnvironment` (`AppEnvironment.swift:130-134`). Signed-out bookmark, note, and position writes go to `GuestDataStore` (`UserLibraryModel.swift:226-249,276-298,397-423`). That store uses SwiftData models and explicit saves; note updates and positions remain local (`GuestDataStore.swift:18-31,125-165,245-287`). Folder/membership drafts are local too.
2. Restored Clerk sessions invoke `completeSignIn` from `RootView.swift:89-110`; custom sign-in completions call it from onboarding and Main tabs. `completeSignIn` waits up to 15 seconds for Convex auth (including `loginFromCache`), ensures the current user row, adopts server preferences, then snapshots six guest draft groups into `GuestMergePlanner.makePayload` (`AppEnvironment.swift:208-239,453-469`). Planner output is detached from later local writes.
3. If payload is nonempty, the app awaits `guestMerge:mergeGuestData`; on a successful mutation response it calls unconditional `guestData.clearAll()` (`AppEnvironment.swift:248-320`; `GuestDataStore.swift:290-302`). A note or position saved after the snapshot but before this await returns is absent from the request and deleted. Transport failure retains the store. A successful response's merged/skipped counts are displayed only as a summary, not used to acknowledge specific drafts.
4. Convex auth-state changes trigger `library.refresh` (`AppEnvironment.swift:193-199`). Signed-in `UserLibraryModel` subscribes to private Saved snapshot and reading progress separately; `subscriptionsActive` prevents reopening while already active (`UserLibraryModel.swift:190-201,428-459`). Sign-out calls Clerk and `handleSignOut`, which refreshes the library; `unsubscribe` cancels subscriptions and clears in-memory private arrays before loading guest drafts (`SettingsView.swift:176-180`; `AppEnvironment.swift:322-329`; `UserLibraryModel.swift:474-490`). There is no explicit account-ID comparison around an in-flight merge or a delivered subscription value in these paths.

## Android

1. `UserLibraryModel` uses `Clerk.sessionsFlow.value.isNotEmpty()` as its signed-in predicate (`HadithlyApplication.kt:90-95`). Guest bookmark, note, folder and position writes launch coroutines that write through `GuestDataStore` (`UserLibraryModel.kt:191-213,245-263,277-293,334-359`). The store uses JSON in app-private `guest_store.json`, a mutex around read/write, and a full-file replacement for `clearAll` (`GuestStore.kt:157-187,286-299`). The mutex serializes each store operation, not the network interval between snapshot and cleanup.
2. `SessionManager.start` reacts to Clerk initialization, Convex auth state, and empty Clerk session lists (`SessionManager.kt:51-92`). `completeSignIn` has a process-local `syncInFlight` guard, waits for Convex authentication with `loginFromCache`, ensures the current user, adopts stored preferences, then obtains one guest snapshot and plans the payload (`:94-139,185-195`). `ConvexRepository.mergeGuestData` sends it as a Convex mutation (`ConvexRepository.kt:357-403`). A successful result is followed by unconditional `guestData.clearAll()` (`SessionManager.kt:140-151`), so a newer local note/position is lost in the same race as iOS.
3. `SessionManager` refreshes the library after merge and on sign-out (`:148-160`). `UserLibraryModel.refresh` subscribes to private Saved snapshot and reading progress when the Clerk predicate is true; `unsubscribe` cancels jobs and empties private in-memory state when false (`UserLibraryModel.kt:160-176,363-435`). `subscriptionFailed` retries with only a boolean signed-in check (`:400-419`). The process-local `syncInFlight` flag has no account owner or persisted generation, and `launchSessionSynced` is a single boolean. Neither proves safe behavior across sign-out, account switch, process restart, or stale emissions.

## Server receipt and proof boundary

`guestMerge:mergeGuestData` derives the owner using `requireIdentity` and the verified Clerk JWT; no client-supplied user ID is accepted (`backend/convex/guestMerge.ts:24-91`). Its transaction applies folders, facets, notes and positions with conflict/idempotence rules, then returns aggregate merged/skipped counts (`:93-107,250-322`). A skipped count can mean existing/newer cloud data or a missing target; it is not a per-draft receipt that justifies deleting every local entry. The local red diagnostic proves the unconditional-cleanup race; it does not prove SDK cancellation, JWT account ownership after an await, private-subscription isolation, or iOS→Android/Android→iOS sync. Those remain explicit A2 verification gates.
