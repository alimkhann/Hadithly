# A2 current sync model — grounding for design review

This describes the October 18 checkout and local diagnostic. In domain terms, a Saved item has independent bookmark, favorite, note, and optional folder-membership facets; a reading position has a semantic hadith anchor and a disposable page hint (`CONTEXT.md`). Reading and saving work signed out. The current guest-to-account transfer is a one-shot snapshot on sign-in, followed by private Convex subscriptions.

1. **Guest storage and capture.** iOS writes signed-out drafts to SwiftData through `GuestDataStore`; Android writes them to an app-private JSON store through `GuestDataStore` under a mutex. Both include Saved facets, folders/membership, and positions. On sign-in, iOS `AppEnvironment.completeSignIn` and Android `SessionManager.completeSignIn` wait for Convex authentication, call `users:ensureCurrentUser`, adopt stored preferences, then pass a snapshot to `GuestMergePlanner`. The planner filters/deduplicates invalid draft data and produces a detached payload. Later local edits are outside that payload. Android's mutex serializes store operations, but does not span the network await. Sources: `ios/Hadithly/App/AppEnvironment.swift:208-320`, `android/app/src/main/kotlin/com/hadithly/app/core/session/SessionManager.kt:94-151`, and the native trace in `/tmp/hadithly-sync-native-trace.md`.

2. **Authenticated merge.** Both clients call `guestMerge:mergeGuestData` as a Convex mutation. The server derives the account through `requireIdentity` from the verified Clerk JWT, looks up the user row, and never accepts a caller-provided user ID. One mutation transaction resolves folders, applies legacy bookmark/favorite/note rows and canonical Saved items, then applies positions. A thrown error aborts the transaction; a lost response after commit leaves the client uncertain. Folder names resolve to an existing same-owner normalized name or a new folder; local folder IDs only map within the request. Sources: `backend/convex/guestMerge.ts:24-123`, `/tmp/hadithly-sync-server-trace.md`.

3. **Conflict behavior and response.** Existing bookmark/favorite adds are skipped; Saved bookmark/favorite timestamps keep the earliest add. A note changes only when its incoming `updatedAt` is strictly later than the stored note. V2 Saved merges facets independently, but supplied folder membership can replace a newer cloud move without a timestamp comparison; omitted facets preserve cloud values and no removal is represented in this merge. A position is resolved from its semantic anchor (potentially to a nearby permissible anchor when the exact one is gone) and replaces the collection position only when its timestamp is later. Missing hadith targets and losing or duplicate values can all contribute to `Skipped`. The mutation returns ten aggregate merged/skipped counters, with no per-folder, facet, membership, draft-revision, or resolved-position receipt. A `savedItemsMerged` row can therefore contain a losing note or ignored membership. Sources: `backend/convex/guestMerge.ts:125-377`, `backend/convex/library.ts:587-628,1045-1143`.

4. **Cleanup and readback.** On any successful mutation response, both sign-in callers call unconditional `guestData.clearAll()`; they use the counters only for a user-facing summary. Transport failure retains the guest store. Signed-in `UserLibraryModel` then reads the JWT-scoped `library:listSavedSnapshot` and separate `library:listReadingProgressDetailed` subscriptions. The Saved query combines canonical and legacy facets and filters missing hadith targets; the position query can resolve stale anchors. Sign-out refreshes the library, cancels subscriptions, clears in-memory private arrays, and reloads guest storage. The query authorization establishes server-side ownership, while a mutation response by itself does not establish native readback or delivery to another device. Sources: `ios/Hadithly/App/AppEnvironment.swift:248-329`, `android/app/src/main/kotlin/com/hadithly/app/core/session/SessionManager.kt:128-160`, both `UserLibraryModel` implementations, `backend/convex/library.ts:837-899`.

**Proved locally:** The real iOS SwiftData and Android JSON stores lose a newer note or position written after payload capture when the current cleanup runs. The Android positive control observed those drafts before cleanup. See `docs/product-program/sync-design/current-trace.md` and its `/tmp/hadithly-guest-merge-race-*` diagnostic artifacts. Aggregate counts also cannot distinguish all accepted versions, conflicts, missing targets, or a transformation from the submitted position, so they do not justify deleting every local draft.

**Still unverified:** The diagnostic did not run Clerk sign-in, Convex, or two devices. iOS has no explicit in-flight sign-in guard in this path; Android has a process-local `syncInFlight` flag and a single launch-session flag. Neither client checks a captured account identity/epoch around the merge completion or subscription emission. Behavior across sign-out, account switch, cancellation, process restart, delayed responses, stale subscriptions, and iOS→Android/Android→iOS delivery remains an open A2 gate (`docs/PRODUCT_PROGRAM.md:29`). The current source trace supports a risk, not a claim that each account transition fails in practice.
