# A2 arena cross-judge (read-only)

Scores are 1–5 against the **full A2 end state**, not just the reproduced `clearAll` race.

| Criterion | A: versioned guest snapshot | B: claimed partition + account outbox |
| --- | ---: | ---: |
| Exact accepted-version preservation | 4 | 5 |
| Cross-account attribution and stale rendering | 3 | 4 |
| Eventual, bounded retry | 3 | 4 |
| Restart and idempotence | 3 | 4 |
| Interface depth / smallest complete diff | 4 | 3 |
| Meaningful verification path | 3 | 4 |

**Recommend B as the base, with a bounded implementation sequence.** Its atomic guest claim opens a fresh guest generation before network work, so a racing write belongs wholly to the claimed account partition or the new guest partition. Frozen operation IDs/revisions and exact receipts make cleanup a settlement of the submitted version, not deletion of a mutable store. B also addresses a real adjacent A2 gap: both signed-in `UserLibraryModel` implementations currently send Saved and position mutations directly, often swallowing failures (`ios/Hadithly/Core/Saved/UserLibraryModel.swift:226+`; `android/.../core/data/UserLibraryModel.kt:190+`). A’s durable guest worker leaves those account writes on a separate, weaker path. B’s deeper consumer interface is worth the larger diff if the scope is kept to private Saved, folders and semantic positions.

**Graft A’s strict receipt discipline into B.** Require exactly one result for every submitted operation ID and revision; classify exact semantic preservation, a different cloud winner, rejection, and transformed position separately. A winning bookmark must never acknowledge a losing note or ignored membership in the same Saved item. Keep A’s dependency mapping for folder creation before membership, explicit owner+hadith indexing, and source-level tests for mixed outcomes. Make reconciliation automatic for ordinary cloud winners while retaining the losing value privately for recovery; no required manual conflict queue. The recovered value needs a finite lifecycle tied to export and erasure, not silent ring-buffer eviction.

**Fix these B gaps before implementation:**

- `openBinding` must return the JWT-verified principal together with its capability. Compare that principal to the captured Clerk account **before** claiming guests or dispatching sensitive operations. `applyBatch` must verify capability owner equals its own JWT owner before any private write. No client-supplied user ID is an authorization input. The present SDK’s queued mutation/token behavior is unknown; prove it with a controlled adapter and a real auth transition instead of describing it as observed.
- Tag both private Saved and position query responses with their JWT-verified owner, and check owner plus local epoch at the collector before rendering. A local epoch alone cannot prove that a queued subscription opened with the expected token. Sign-out and A→B switch must synchronously invalidate collectors and private projection; old receipts can settle only their captured partition.
- Current `users:deleteCurrentUser` and `users:exportCurrentUserData` know nothing about the proposed binding, receipt ledger, local pending or recovery stores (`backend/convex/users.ts`). Deletion must revoke bindings, delete server receipts and account-local pending/recovery data, and prevent late work from recreating private rows. Export must include user content held only in local pending/recovery and any content retained in server receipts, or keep receipts content-free and document that boundary. Test deletion with a frozen in-flight batch and repeat deletion.
- A time-expired receipt cannot be replayed as a fresh add after a later delete. Prefer a durable settle-then-ack protocol: persist local settlement before server acknowledgement; retain unacknowledged receipt/digest records and never expire them by wall clock alone. Bound admission and compaction explicitly. If a bound is hit, fail closed with recoverable local data rather than discarding or replaying intent. Tombstones and direct legacy mutations must share the same compare rule while old clients coexist.
- B sketches `FolderCreate` and set/absent facets but does not finish folder rename/delete/undo and existing toggle/restore behavior. Enumerate every current private write entry point on both apps and migrate the callers with the domain rule in the same unit; otherwise a direct mutation can race the outbox. Cap bytes and operations, but do not truncate a nearest-anchor search into an incorrect “preserved” receipt.

**Sequence to keep the diff reviewable:** (1) land bounded typed operation/receipt rules, owner binding, ledger, deletion/export coverage, and backend conflict/idempotence tests; (2) implement each native durable partition and coordinator behind the existing library methods, turning the real SwiftData/JSON red diagnostics green through the production sign-in path; (3) migrate all account Saved/folder/position write callers and fenced subscriptions on both platforms before claiming A2 complete; (4) exercise offline/restart/lost response, newer write/delete, A→B switch, stale emission, and deletion with real stores and controlled transport; (5) run approved real iOS→Android and Android→iOS sign-in/write/readback. Local green tests prove the cleanup race and deterministic lifecycle logic, **not** Clerk/Convex account binding or two-device delivery. Keep those gates open until observed.
