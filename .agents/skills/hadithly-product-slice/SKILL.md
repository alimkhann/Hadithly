name: hadithly-product-slice
description: Scope a Hadithly product request into one verifiable session before implementation.
---

Read the current checkpoint required by AGENTS.md. Use docs/PRODUCT_PROGRAM.md
to retain the broader objective and current owner deferrals.

Turn the request into a short task contract:

- Reader problem and exact journey, including platform and language.
- Observed evidence versus assumptions, with one question only if a product
  decision cannot be resolved from the current record.
- One outcome, an explicit scope boundary, and observable acceptance criteria.
- Smallest useful verification on each native platform, or the named parity-only
  exception. Separate fixture, live-service, physical-device and language approval.
- Dependencies, approval-sensitive actions, and the checkpoint at which to hand off.

For broad requests such as "fix Android" or "reduce Convex usage", propose the
first diagnostic unit and its measurement before implementation. Planning does
not authorize the backlog. Reuse existing records; create a separate spec only
when the decision needs more than a short checkpoint.

When comparing options, give a recommendation and its tradeoff. Keep product
decisions with the owner and resolve observable technical questions by inspection
or a bounded experiment. Finish with a ready-to-run next-session prompt that
names the outcome, evidence, stop point and remaining gates.
